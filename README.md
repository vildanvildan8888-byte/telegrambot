# Telegram-бот доставки «Вкусный двор»

Бот на Node.js, Telegraf и PostgreSQL. Telegram обновления принимаются по webhook; меню, корзина, оформление заказа, профиль, статусы и административные уведомления используют существующие обработчики и схему базы данных.

## Что умеет

- показывает категории и доступные товары с описанием, ценой и необязательной фотографией;
- меняет количество товаров в корзине и считает сумму;
- оформляет заказ: имя, телефон, адрес, комментарий и наличные/карту курьеру;
- присваивает каждому заказу уникальный номер;
- отправляет заказ в чат администратора и даёт кнопки принятия, отмены, готовки, передачи курьеру и завершения;
- сообщает клиенту об изменении статуса;
- хранит пользователей, корзину и заказы в PostgreSQL; начальное меню заполняется при старте.
- предоставляет `GET /health` для проверки состояния Web Service.

## Требования

- Node.js 20 или новее;
- PostgreSQL 15 или новее (либо Docker Desktop для локальной базы);
- токен бота от @BotFather и числовой Telegram ID администратора.

## Запуск на Render Web Service

1. Создай в Render базу PostgreSQL и Web Service для репозитория `vildanvildan8888-byte/telegrambot`.
2. Укажи параметры сервиса:

   | Настройка | Значение |
   | --- | --- |
   | Service type | Web Service |
   | Runtime | Node |
   | Branch | `main` |
   | Root Directory | пусто |
   | Build Command | `npm install` |
   | Start Command | `npm start` |
   | Health Check Path | `/health` |
   | Instance Type | Free для тестирования |

3. Добавь переменные окружения до первого запуска:

   - `BOT_TOKEN` — токен от @BotFather;
   - `DATABASE_URL` — Internal Database URL созданной базы Render Postgres;
   - `ADMIN_ID` — числовой Telegram ID администратора;
   - `WEBHOOK_URL` — **базовый публичный URL** сервиса, например `https://tasty-yard.onrender.com`. Не добавляй `/telegram/webhook`: приложение сформирует endpoint само;
   - `WEBHOOK_SECRET` — необязательный секрет из букв, цифр, `_` или `-`. Если оставить пустым, приложение стабильно вычислит секрет на основе `BOT_TOKEN`.

   Render выдаёт домен вида `https://<service-name>.onrender.com`. Выбери имя сервиса и укажи соответствующий URL в `WEBHOOK_URL`. Порт `PORT` задаёт Render автоматически; приложение слушает его на `0.0.0.0`.

При старте приложение проверяет конфигурацию, подключается к PostgreSQL, применяет миграции и демо-меню, запускает HTTP-сервер, затем вызывает Telegram `setWebhook` с endpoint `/telegram/webhook`. Повторный запуск обновляет настройки того же webhook и не включает long polling. Обновления не удаляются при переустановке webhook. Входящие запросы проверяются по заголовку `X-Telegram-Bot-Api-Secret-Token`.

**Ограничения бесплатного тарифа:** Render останавливает Free Web Service после 15 минут без входящих запросов; холодный запуск может занять около минуты. Поэтому первые сообщения после простоя могут обрабатываться с задержкой. Шаги незавершённого оформления хранятся в памяти и сбрасываются при перезапуске; корзина и заказы остаются в PostgreSQL. Бесплатная база Render Postgres действует ограниченное время (сейчас 30 дней). Это подходит для демо и проверки, но не для постоянной рабочей доставки. [Подробнее о лимитах Free](https://render.com/docs/free).

## Локальный запуск

1. В этой папке создай локальный файл `.env` на основе `.env.example`.
2. Заполни `BOT_TOKEN`, `ADMIN_ID`, `DATABASE_URL` и `WEBHOOK_URL`. Для локальной машины нужен доступный извне HTTPS URL webhook (например, через HTTPS tunnel); локальный адрес `localhost` Telegram использовать не сможет. Не отправляй токен в чат и не добавляй `.env` в Git.
3. Запусти локальную PostgreSQL-базу, например через Docker Desktop:

   ```powershell
   docker compose up -d postgres
   ```

   Если используешь другой PostgreSQL, поменяй `DATABASE_URL` в `.env`.

4. Установи пакеты и запусти бота:

   ```powershell
   npm install
   npm start
   ```

   При запуске приложение автоматически создаёт таблицы, добавляет демонстрационное меню и устанавливает webhook. Затем отправь боту `/start` в Telegram.

Чтобы бот мог отправить первое личное уведомление владельцу, открой чат с ботом под аккаунтом администратора и нажми `/start`. Если `ADMIN_ID` — ID группы, добавь туда бота.

## Настройки

- `BOT_TOKEN` — токен Telegram-бота;
- `DATABASE_URL` — PostgreSQL connection string;
- `ADMIN_ID` — числовой Telegram ID одного администратора;
- `WEBHOOK_URL` — публичный базовый HTTPS URL приложения; полный путь добавляется автоматически;
- `WEBHOOK_SECRET` — необязательный секретный заголовок webhook; если не задан, стабильное значение выводится из токена бота;
- `PORT` — порт HTTP-сервера; Render задаёт его автоматически, локально по умолчанию используется `3000`;
- `RESTAURANT_ID` — идентификатор ресторана, по умолчанию `tasty-yard-demo`;
- `HELP_CONTACT` — контакт поддержки, например `@restaurant_support`.

Валюта демо-меню — узбекский сум. `photo_url` у товара может быть URL изображения или Telegram file ID; если поле пустое, бот отправляет карточку без фотографии. Оплата в этой версии выбирается как наличными или картой курьеру, платёжный провайдер не подключён.

## Структура

```text
migrations/                 схема PostgreSQL
src/
  bot/                      запуск Telegraf, клавиатуры и обработчики
  http-server.js            health endpoint и защищённый Telegram webhook
  webhook.js                URL, секрет, порт и проверки конфигурации webhook
  config.js                 чтение и проверка переменных окружения
  database/                 пул, миграции и начальное меню
  domain/                   форматирование и правила статусов/формы
  repositories/             параметризованные запросы к PostgreSQL
  services/                 действия каталога, корзины и заказов
tests/                      модульные тесты бизнес-правил
```

Данные каталога связаны с `RESTAURANT_ID`, чтобы в дальнейшем добавлять рестораны с отдельными меню. Состояние заполнения заказа хранится в памяти процесса; корзина и оформленные заказы — в базе. Для нескольких параллельных экземпляров бота следует вынести сессию оформления в PostgreSQL/Redis.
